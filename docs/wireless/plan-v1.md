# 小智 Passport 无线对话采集与外部 LLM 长期记忆方案 V1

**日期**：2026-11-20  
**项目**：[`itsnone-liu/xiaozhi-passport`](https://github.com/itsnone-liu/xiaozhi-passport)  
**定位**：面向执行 Agent 的实施与验证任务书  
**当前阶段**：设备侧 STT/TTS 串口验证已报告通过；下一目标是**脱离 USB、无线采集、远程 Ubuntu 接收**  
**本轮范围**：无线文本采集最小闭环及其与未来记忆服务的接口；不建设完整记忆系统

---

## 0. 决策与边界（已确定，不再反复讨论）

1. **保留小智官方云语音服务**：不自建小智语音服务端，不替换现有 ASR/LLM/TTS 语音链路。主要理由是目前官方链路的语音质量及使用体验。
2. **生产环境不得依赖 USB/串口物理连线**：串口日志仅用于开发和故障诊断；设备实际使用时为电池供电。
3. **Passport 通过 Wi-Fi 直接向美国 Ubuntu 公网服务器上传文本**：家中连家庭 Wi-Fi，外出连手机热点；手机只提供网络，不做数据转发 App。
4. **长期记忆采用外部 LLM + 现成记忆引擎**：后续优先比较 Hindsight、PowerMem，必要时以 Mem0 为对照；不自行重造复杂的提取、去重、更新和检索算法。
5. **采集与记忆解耦**：设备只负责产生并可靠发送 STT/TTS 文本事件；Ubuntu 端负责持久化、整合、调用外部 LLM 和 MCP 接入。
6. **本轮先做最小样机，后做规模化**：不提前引入分布式队列、复杂管理后台、庞大的身份体系或多租户平台。
7. **儿童对话属于敏感数据**：禁止公网明文上传、禁止把原始对话和密钥提交到 GitHub、禁止默认永久保留全文。

## 3. 通信方案：先评估，再选型

### 3.1 首选候选：HTTPS POST 到美国 Ubuntu

原因：公网环境下 TLS、服务端框架、认证、监控和幂等机制都成熟，不必自己设计新的加密协议。接收端可使用 Nginx/Caddy 终止 TLS，应用服务只监听本机地址或容器内网。

但**不得直接预设 HTTPS 一定适合当前 ESP32-C3**。现有固件已连接官方 MQTT/TLS，新增 TLS 会话可能受内存和任务调度影响。必须先在真实固件中做**空连接/小包/连续上传的峰值实验**。

实现要求：

- 复用 ESP-IDF 5.5.3 已提供的 HTTP/TLS 能力和 CA 校验，**不能关闭证书验证**；避免从零实现密码学。
- 配置服务端域名，不在固件中散布可变公网 IP；支持证书正常续期。
- 上传逻辑运行在独立、低优先级任务中，限时、限频，短连接或持久连接以实测资源决定。
- 对端使用设备级认证凭证；通过受控配置/NVS 保存，不能写进公开代码或日志。
- 服务器收到并**成功持久化**后才返回 ACK；不是收到 TCP 包就视为成功。

### 3.2 HTTPS 不通过时的备选评估

按顺序研究：

1. 调整发送批次、连接复用、缓冲区配置、任务栈、证书链与 TLS 资源占用，但不得牺牲语音稳定性。
2. 评估轻量的加密报文方案，例如**已有密码学库**支持的 AEAD + 有界重传/ACK；必须设计唯一 nonce、序号、防重放、密钥轮换与认证，且经过负载与安全复核。
3. 评估其他可复用的标准轻量安全传输方案。**不得将无加密 UDP/TCP 明文作为生产兜底。**

不建议：将文本写入官方小智 MQTT Broker 的自定义 Topic（没有取得官方服务端授权或路由能力的证据）；或依赖手机常驻 App 转发。

**选型门槛**：实测证明“不增加音频卡顿、不会导致 OOM/重启、断网可恢复、儿童数据传输保密”以后，才能宣布路线确定。

## 4. 设备端最小改造设计

### 4.1 事件来源

在当前已经验证的 `stt` 与 `tts sentence_start` 分支，**只复制必要数据并投入队列**。不要在消息处理回调中调用 HTTP、等待 ACK、读写 Flash 或执行记忆分析。

建议生成事件字段：

```json
{
  "schema_version": 1,
  "device_id": "opaque-device-id",
  "boot_id": "random-boot-id",
  "seq": 101,
  "session_id": "cloud-session-id-or-empty",
  "direction": "user",
  "text": "今天我们继续昨天的故事",
  "monotonic_ms": 1234567,
  "captured_at": null
}
```

- `direction` 仅取 `user|ai`；AI 多句回复按多个事件记录，并保留顺序。
- `device_id` 是上传设备身份，不等于孩子身份；`session_id` 是云端会话身份，不等于 `speakerId`。
- `boot_id + seq` 构成设备侧唯一事件标识；服务器按该键做幂等。
- 设备时间如果未同步，`captured_at` 可以为 `null`；服务器补 `received_at`，不能把服务器接收时间伪装成真实说话时间。
- 文本采用 UTF-8；需要验证引号、反斜杠、换行、Emoji、制表符、超长回复和分片情况。JSON 必须通过安全序列化生成，不能字符串拼接。

### 4.2 队列和任务

- 有界 RAM 队列，容量和单条上限由内存实测决定；严禁无界分配。
- 入队优先于上传，不允许上传任务阻塞音频回调。
- 队列满时遵循显式丢弃策略，并增加 `dropped_events`、`dropped_bytes`、原因计数；不可悄悄丢失却宣称“完整记忆”。
- 本轮优先做 RAM 缓冲；如需要跨断电可靠性，再单独评估 Flash 持久队列、磨损、空间及 OTA/分区风险。不为小样片先设计复杂离线数据库。
- 网络失败时采用指数退避并带抖动；不得高速重试消耗电量或挤占官方云链路。
- 深睡前可以尝试限时发送，但不能为了保日志让设备长期不能休眠。

### 4.3 网络状态

- 复用现有 Wi-Fi 管理能力，不自建第二套网络配置体系。
- 明确验证“家庭 Wi-Fi ↔ 手机热点”的配置和切换流程：是否支持保存多个 SSID、重连优先级、连接超时、切换是否干扰官方语音链路。
- 手机热点仅需能够访问美国 Ubuntu 的 HTTPS 域名；不要求设备和服务器处于同一局域网。
- 如果设备在某些热点上无法联网，记录 DNS、TLS、端口连通性和 Wi-Fi 频段（ESP32-C3 仅 2.4 GHz）等具体故障证据，不猜测。

## 5. 美国 Ubuntu 服务器接收端

### 5.1 最小服务接口

推荐先做一个轻量服务，例如 Python FastAPI 或 Go（按现有栈选择），只暴露一个接收入口：

```http
POST /v1/device-events
Content-Type: application/json
Authorization: Bearer <device-secret>
```

批量提交示例：

```json
{
  "schema_version": 1,
  "device_id": "opaque-device-id",
  "events": [
    {
      "boot_id": "boot-abc",
      "seq": 101,
      "session_id": "sid-123",
      "direction": "user",
      "text": "我们继续找宝石",
      "monotonic_ms": 1234567
    },
    {
      "boot_id": "boot-abc",
      "seq": 102,
      "session_id": "sid-123",
      "direction": "ai",
      "text": "上次我们停在山洞入口。",
      "monotonic_ms": 1235000
    }
  ]
}
```

服务端应当：

1. 验证 HTTPS、设备凭证、请求体大小、字段格式和最大事件数。
2. 确认认证主体和载荷 `device_id` 一致，不信任客户端自报身份。
3. 在一个事务内将新的事件持久化；相同 `(device_id, boot_id, seq)` 重发不重复写入。
4. 返回已落盘事件的 ACK/序号。**部分成功的 ACK 必须可表达**，或者全请求原子提交。
5. 为每个事件记录 `received_at`、ingest 版本和必要诊断信息；诊断日志默认不输出原始对话文字。
6. 限流、超时、防重放、失败告警；监听端口最小暴露，不开放数据库端口。

### 5.2 数据层（本轮够用即可）

- 初期可以使用 SQLite WAL（单设备、轻负载）。
- 原始事件表与“供记忆引擎消费的对话段”分开，便于重放、纠错及排查漏句。
- 会话整合按 `device_id + session_id` 分组；`session_id` 为空时退回基于间隔/状态的启发式归并，并标记低置信度。
- 记忆系统处理原始文本前先做必要脱敏与使用权限控制。保留期限配置化，原始对话不永久留存；支持按设备/用户删除。

### 5.3 外部 LLM 的后续接口

暂不绑定具体模型或框架。定义可消费的对话批次：

```json
{
  "device_id": "opaque-device-id",
  "session_id": "sid-123",
  "turns": [
    {"role": "user", "content": "我们继续找宝石"},
    {"role": "assistant", "content": "上次我们停在山洞入口。"}
  ],
  "source_event_ids": ["boot-abc:101", "boot-abc:102"]
}
```

后续外部 LLM 负责“是否值得记住/事实更新/矛盾处理”；Hindsight 或 PowerMem 负责记忆存储和检索。**儿童数据发往第三方 LLM 前，须先确认服务商数据保留与训练政策、取得监护人同意、控制最小必要数据传输。**

## 6. 身份与 MCP 衔接：先区分三种 ID

| 标识 | 来源 | 用途 | 不应做的事 |
|---|---|---|---|
| `device_id` | 固件/接收服务 | 上传授权、设备隔离 | 直接等同孩子身份 |
| `session_id` | 小智云会话文本事件 | 同一会话内归并 | 用作跨会话长期身份 |
| `speakerId` | 小智 MCP 元数据中的声纹标识 | 小智 MCP 读记忆的使用者定位 | 假定能从 STT/TTS 事件中直接获得 |

**关键未解决问题**：设备端上传的 `session_id/device_id` 如何与 MCP 调用时的 `agentId/speakerId` 绑定？

短期单设备场景：使用**人工确认的一次性设备 → 记忆账户映射**进行闭环测试；但这只适用于确认同一孩子使用设备的情况。多人共用设备时，不能把所有聊天直接写到某个孩子的画像中。

长期方案：若没有可信声纹映射/设备侧使用者确认，就将无法判定归属的事件放入未归属队列，禁止污染任何具体孩子的长期记忆。

**读取侧另设测试**：外部 LLM 能自动写入记忆，不代表官方小智云一定会主动调用 `memory.search`。此项独立评估，可保留少量提示词辅助，但不要将其当成已解决。

## 7. 分阶段执行任务与停点

### P1-0：现状核对（只读，禁止贸然改固件）

任务：

- 核对当前设备固件版本、实际源码仓库及 `textlog` 补丁 SHA；确认当前可恢复的全量 Flash 备份和还原步骤。
- 对照 README 与最新补丁文档，整理真实完成项、未完成项。
- 核查 GitHub 仓库可见性及现存敏感信息；保留准确的“公开/私有”检查结果。
- 确认现有 Wi-Fi 配网方式和能否切换家用 Wi-Fi、手机热点。

交付：`docs/wireless/P1-0-baseline.md`  
**停点**：没有可恢复固件备份、无法确定补丁所基于源码时，不进入刷机。

### P1-1：通信资源探针

任务：

- 固件先增加**不包含真实儿童对话**的测试事件上传能力；优先测 HTTPS/TLS。
- 测空载、语音识别中、TTS 播放中、长故事、连续上传、Wi-Fi 重连时的：
  - free heap / minimum free heap；
  - largest free block；
  - 新任务 stack high-water mark；
  - 上传耗时与错误率；
  - 音频卡顿、重启、watchdog、耗电/续航变化。
- 与相同固件未启用上传时的基线对照。

交付：`docs/wireless/P1-1-transport-probe.md`，必须包含失败记录。  
**停点**：如 HTTPS 造成 OOM、音频中断、明显卡顿或 TLS 证书验证无法正确工作，**不得以关闭 TLS 校验或明文上传绕过**；转入备选通信方案论证。

### P1-2：无线传输最小闭环

任务：

- 在已验证的 STT/TTS 回调点复制事件 → 有界队列 → 异步上传。
- Ubuntu 建立最小接收服务、幂等落库和 ACK。
- 通过固定测试语料验证中文、标点、长回复、多个 `ai` 分句、会话 ID 与顺序。
- 电脑 USB 断开，设备用电池供电，通过家庭 Wi-Fi 直连美国服务器。

交付：
- 固件补丁及 SHA；
- 服务器最小接收程序与配置样例（无密钥）；
- `docs/wireless/P1-2-home-wifi-e2e.md`；
- 数据库中可验证的**脱敏**事件示例。

**停点**：任何“只能看到串口、服务器不能独立收到文本”的情况均不算通过。

### P1-3：手机热点与长期运行

任务：

- 同一固件由家庭 Wi-Fi 切换到手机热点，手机无中转 App，设备仍可正常与官方小智云通话并上传至美国 Ubuntu。
- 验证断网 30 秒、数分钟、设备重启、深睡唤醒、人工打断、连续 20 轮、长故事、重复 ACK/重传。
- 统计是否丢句、乱序、重复、错误归并；模拟接收端暂时不可用。
- 记录是否需要用户手动切换 SSID、重新配网或热点设置。

交付：`docs/wireless/P1-3-hotspot-soak.md`，含成功率、漏失、原因和资源对照。  
**停点**：若热点上只能正常聊天却不能上传，或者上传干扰官方语音链路，不进入记忆引擎接入。

### P2：记忆框架对比（**P1 全部通过后**）

- 从已采集对话中构建脱敏基准集，分别用相同外部 LLM 测试 Hindsight、PowerMem；可选 Mem0 对照。
- 评估长期兴趣、经历、纠错、事实冲突、故事连续性、中文检索、错记率、无依据推断、删除能力与运行成本。
- MCP 读取通过现有小智云工具接口，不另建语音服务端。
- 单独测“自动写入率”和“主动检索触发率”，不要合成一个模糊的成功率。

交付：`docs/memory/P2-memory-engine-evaluation.md`。**本方案不要求现在执行 P2。**

## 8. 必须通过的验收标准

| 项目 | 通过标准 |
|---|---|
| 真正无线 | 设备断开 USB 且电池供电，Ubuntu 仍收到 STT/TTS |
| 双网络 | 家用 Wi-Fi 和手机热点均能到达同一美国服务器 |
| 官方云不受影响 | 既有语音唤醒/对话/播放/打断不因上传失效；与基线比较无可感知新增卡顿 |
| 文本正确 | 中文 UTF-8、分句顺序、会话归属可验证；漏失有计数 |
| 可靠性 | 服务端持久化后 ACK；重发不产生重复事件；断网不致崩溃 |
| 资源 | 无 OOM/watchdog/意外重启，最小堆和任务栈余量有实测报告 |
| 安全 | 公网传输加密且验证服务端证书，设备认证，凭证不入仓库 |
| 隐私 | 原始儿童对话不出现在公开 GitHub、普通系统日志、调试截图和测试报告中 |
| 可回退 | 保留固件备份和可执行恢复路径 |

> **完整性声明规则**：如果只有部分句子、断网导致不可恢复丢失，报告必须写清是 *best-effort capture*，不能表述为“完整自动记录所有聊天”。

## 9. Agent 开发限制

- 不得擅自把小智官方云切换到自建服务端。
- 不得删除或破坏既有配网、OTA、官方小程序、设备身份信息和恢复分区。
- 不得为了保存日志而长期阻塞设备音频线程。
- 不得将传输令牌、家庭网络凭据、儿童对话文本写入 Git 历史。
- 不得在没有资源实测前下结论“HTTPS 一定可行”或“UDP 必然更轻更好”。
- 不得将设备身份、会话身份和声纹身份混同。
- 代码与测试产物按阶段提交，P1-1 失败应如实记录，**不靠降低安全性硬凑 PASS**。
- P1-3 完成之前，不启动大规模记忆引擎开发。
